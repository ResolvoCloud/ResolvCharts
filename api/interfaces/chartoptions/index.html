flow?

Section titled “flow?”

optional flow?: boolean

Defined in: types.ts:235

Continuous-flow mode for xy charts: points ease toward their targets with a slight right-to-left ripple so transitions read as a wave, not a snap. Unless animate is a number, the tween duration auto-follows the measured append() cadence (EMA), so the pan finishes exactly as the next sample arrives — perpetual motion, zero lag.

maxPoints?

Section titled “maxPoints?”

optional maxPoints?: number

Defined in: types.ts:248

For xy charts: hard cap on retained datapoints during append() — memory bound for live mode. A few extra points may be kept transiently so dropped points slide off-screen smoothly. When window is unset, the view shows the last maxPoints.

renderer?

Section titled “renderer?”

optional renderer?: "auto" | "canvas" | "webgpu"

Defined in: types.ts:258

Render backend for xy series (line/area/sparkline/scatter). "canvas" uses Canvas2D. "webgpu" rasterizes series on the GPU — instanced lines, point sprites, compute decimation — while axes, grid, and tooltips stay on Canvas2D. "auto" (default) engages WebGPU once the point count crosses gpuThreshold, else Canvas2D. Unknown to older browsers → silent fallback to Canvas2D.

gpuThreshold?

Section titled “gpuThreshold?”

optional gpuThreshold?: number

Defined in: types.ts:265

For renderer: "auto": total visible xy points (x-length × series) at which the GPU path engages. Below this, Canvas2D is faster. Once the GPU attaches it stays attached for the chart’s lifetime. Default: 100,000.

gpu?

Section titled “gpu?”

optional gpu?: object

Defined in: types.ts:276

WebGPU adapter options — only used when renderer resolves to WebGPU. powerPreference picks the discrete GPU on dual-GPU systems; compat requests compatibility mode (GLES 3.1 / D3D11 reach); timing enables GPU-side pass timing via “timestamp-query” when the adapter supports it (note: browsers require cross-origin isolation and quantize to ~100 µs — dev/profiling use only); allowFallback accepts software adapters like SwiftShader (off by default — usually slower than Canvas2D).

yMin?

Section titled “yMin?”

optional yMin?: number

Defined in: types.ts:307

Pin the y-axis domain. Each bound overrides the auto-fitted value — unset ends still auto-fit. E.g. { yMin: 0, yMax: 100 } frames a utilization chart honestly; { yMin: 0 } zero-anchors without a ceiling. Values exceeding the bounds are clipped at the plot edge.
