Render cost — warm vs cold

Warm re-renders an unchanged frame — the whole-frame memo early-returns. Cold rewrites the data first, so each timed render pays the full path.

tip: scatter @1M on canvas ~140 ms vs webgpu ~0.2 ms — instanced quads vs arc-per-point

Streaming — 50k rolling window

One append() per animation frame for four seconds. Ours shifts a ring buffer; competitors re-render the whole window per point.

Methodology

Submit vs updateOurs times render(1). Theirs times the documented refresh on unchanged data — Chart.js update('none'), ApexCharts updateSeries(), Highcharts setData+redraw. They re-parse data we hold as typed arrays; that's the real cost a caller pays.
Fair controlsAnimations, tooltips, legends, markers off. Chart.js "+dec" = built-in decimation; Highcharts "+boost" = WebGL module (+~50 kb).
Warm vs coldSince v0.6 the whole frame is memoized — unchanged views early-return. Streaming and zoom still pay the full path every frame.
CaveatEven discounting the update-path asymmetry, streaming fps and init times — which share no such asymmetry — show the same ordering.
